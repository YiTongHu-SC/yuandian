# 开发与验证

## 环境与命令

需要 Node.js 20 或以上版本，无构建步骤。普通画布与本机静态服务可不安装 SDK 运行；开发、完整测试或使用 MCP stdio 前执行 `npm ci`，按锁文件安装官方 `@modelcontextprotocol/server` 及测试用 `@modelcontextprotocol/client` 2.3.1。Windows 使用 PowerShell 启动脚本，其他环境可用 `npm start`。

| 命令 | 作用 |
| --- | --- |
| `npm ci` | 按 `package-lock.json` 安装 MCP 运行与测试依赖，不增加前端构建链 |
| `npm start` | 前台启动 `scripts/dev-server.mjs`，默认 `127.0.0.1:4176`；Ctrl+C 停止 |
| `.\start.ps1` / `Start.cmd` | Windows 后台启动或核对并复用当前目录的服务，打开浏览器 |
| `.\start.ps1 -NoBrowser` | 仅启动或复用服务 |
| `npm test` | 运行 `tests/unit/` 和 `tests/tooling/` 的 Node 测试 |
| `npm run check` | 执行 `scripts/check.mjs` 项目静态检查 |
| `npm run verify` | 依次运行静态检查与全部测试 |
| `npm run build:pages` | 按白名单复制静态应用到 `dist/pages/`，供 GitHub Pages 发布；不生成或上传用户数据 |
| `npm run mcp` | 启动 stdio MCP 服务；通常由 AI 客户端按页面生成的固定配对配置启动，也兼容旧临时令牌环境变量 |
| `npm run mcp:remote` | 启动独立远程 MCP 后端，需设置公开 HTTPS 地址等环境变量；仍只监听回环地址 |

不要直接打开本地 HTML。ES Modules 通过 HTTP 加载；用户日常入口固定为 `http://127.0.0.1:4176/`，更换 host 或端口会使用另一份浏览器站点存储。

重复启动时需确认服务来自同一项目目录。占用端口的服务身份不符时，启动脚本应报错并保留该进程。旧 Python 服务只有在目录核验匹配后才能兼容复用；若要验证新的静态资源访问边界，应使用新的 Node 服务。

MCP 需要支持 `/api/mcp/` 的当前 Node 服务；仅刷新页面不能更新已运行的旧服务代码。确认身份后重启本项目服务，勿结束无关进程。通过页面“AI 接入”配对并生成配置，客户端会以 Node 绝对路径启动 `scripts/mcp-server.mjs`，并传入 `YUANDIAN_URL` 与 `YUANDIAN_MCP_TOKEN`；新流程中的令牌为固定配对客户端凭据，页面 owner 会话与它分离，旧临时令牌流程仍兼容。不要把真实凭据写入源码、测试记录或 Git。配置方法见 [MCP 接入指南](mcp.md)。

本机配对身份只保存到用户私有状态目录：Windows `%LOCALAPPDATA%\Yuandian\Mcp\pairings-<hash>.json`（缺少该变量时为用户目录下 `AppData\Local`）；其他系统 `$XDG_STATE_HOME/yuandian/mcp/pairings-<hash>.json`，未设置时为 `~/.local/state/yuandian/mcp/pairings-<hash>.json`。`hash` 为项目规范路径与本机站点 origin 的 64 位 SHA-256，按项目和实际端口隔离，避免并行测试、worktree 或开发端口覆盖其他服务身份；同一项目同一地址重启保持稳定。不要以仓库内文件、静态资源目录或画布备份作为身份存储。协议测试使用隔离临时目录，不能读取或覆盖用户的真实身份文件。服务端只保存身份元数据，永久授权意愿仅保存在浏览器独立配对 IndexedDB，具体字段和回退规则见 [数据约定](data-format.md#mcp-数据边界)。

GitHub Pages 在 `main` 更新时由 Actions 先执行完整检查，再发布 `build:pages` 的静态产物。远程 MCP 后端独立部署，通过既有 Caddy HTTPS 反向代理，不进入 Pages 产物。模板在 `deploy/remote-mcp/`；运行需设置 `YUANDIAN_PUBLIC_URL=https://stellarcore.games/yuandian-mcp`、`YUANDIAN_ALLOWED_ORIGIN=https://yitonghu-sc.github.io`、`YUANDIAN_PORT=4177` 和 `YUANDIAN_PAIRING_STORE=/var/lib/yuandian-mcp/pairings.json`。生产使用独立 systemd 用户、回环监听、单进程内存授权与私有配对目录；只有设备身份元数据落盘。部署与回退见 [部署说明](deployment.md)。线上与本机数据不自动同步。

服务器连接资料统一放在 [服务器配置目录](../deploy/remote-mcp/config/README.md)。只提交其中指定的脱敏示例，真实连接、密码、私钥和主机公钥记录填写到被忽略的本机文件；已有文件不覆盖。此目录不会被应用或 systemd 自动加载，也不进入静态服务和 Pages 产物。`tests/tooling/server-config.test.mjs` 使用临时 Git 仓库与虚构文件检查实际暂存、HTTP 拒绝访问和构建排除行为，不读取本机凭据。

## 改动与检查

先确认 [产品边界](../PROJECT.md)、[模块职责](architecture.md)和 [数据约定](data-format.md)。纯模型改动保留模型无 DOM 依赖；界面改动使用真实浏览器验证，模块搬迁同时核对两个入口的脚本与样式加载。

`npm test` 用于验证数据、计算和工具行为，`npm run check` 用于发现语法与引用错误。两者不能替代页面操作。无需为轻微文案变化扩写整套测试；新增测试应覆盖实际错误、兼容边界或可观察行为。

MCP 卡片纯操作测试位于 `tests/unit/canvas-mcp.test.mjs`，跨画布模型与 JSON 回导测试位于 `tests/unit/canvas-mcp-workspace.test.mjs`，授权面板的异步控制流测试位于 `tests/unit/canvas-mcp-ui.test.mjs`。临时桥和真实 stdio SDK 客户端测试位于 `tests/tooling/mcp-bridge.test.mjs`、`tests/tooling/mcp-server.test.mjs`；远程 Streamable HTTP 为 `tests/tooling/mcp-remote.test.mjs`。协议测试会用虚构响应与独立回环端口，不访问日常浏览器数据；面板 DOM 替身也只验证授权控制流。它们不能替代真实页面的保存、撤销和交互验证。

远程 MCP 测试需使用真实 Streamable HTTP SDK 客户端核对协议、默认只读、工作区跨画布范围、旧单画布令牌不升级、错误令牌、Origin、超时、断开和版本冲突。本机用真实 stdio SDK 客户端核对固定配对身份以及旧临时 `/session`、`/call` 与配置兼容。配对还需验证持久文件仅含白名单身份字段、签名挑战单次使用且绑定操作、服务重启保留身份但清除活跃会话 / 队列、取消配对后拒绝访问；线上取消配对后为 HTTP 401。固定身份在未授权时仍可初始化和发现六个工具，状态为 `needs_authorization`，内容工具拒绝访问。恢复新 owner 会话后，旧会话不能释放新页会话、旧请求不能借新授权提交或重放。创建须核对 `expectedWorkspaceRevision`，编辑须明确 `boardId`；检查单张 / 全部 JSON 导出与只读允许导出、拒绝新建。模拟浏览器桥返回的结果只证明协议路径。

永久重开提速另核对：授权可选 `tabLock: true` 只在页面实际持有标签页生命周期锁时发送，签名状态返回的活动标签页与会话字段只属于内存；旧客户端省略字段继续兼容。关闭旧页后，即使离开通知未送达，也应由锁探测及匹配 `expectedSessionId` 的撤销建立新会话；记录关闭、重开、恢复的实际时间，不把缩短测试时钟当作真实重开耗时。另保留打开的后台页，确认其持锁时不被自动接管；验证旧会话无持锁标记、锁探测失败时仍按原远程 90 秒 / 本机 10 秒兜底。通过条件撤销期间另建立新会话，应拒绝过期的会话 ID，不误断开新页；恢复或断开竞争时不得重放旧写入。协议与面板替身测试分别覆盖这些边界，再由本轮 GPT 内置浏览器和实际工具确认恢复速度及权限。

随后按本次改动影响，在 GPT 内置浏览器以虚构数据验证一次配对、网页授权、刷新、关闭重开、跨页显式接管及旧页失效。授权时长界面核对“15分钟”“1小时”“永久（直到断开）”及默认一小时；本机 stdio 和线上配对均应覆盖。当前最短时长为 15 分钟，需要验证自然到期恢复时，应等待页面的 15 分钟授权真实到期，不能用人工断开或测试时钟冒充页面到期。永久授权分别验证只读与读写的刷新 / 重开恢复、`expiresAt: null`、原权限保留、失联期间不可读及服务恢复后签名建立新会话；主动断开后跨页和重开均不恢复，旧在途写入不复活。有限授权保持刷新 / 关闭失效，已有配对和旧永久会话没有新授权意愿时不得自动升级。再用当前 Codex 的实际工具核对相应授权状态、默认只读拒写、读写与导出；确认固定配对恢复期间未修改配置或重连服务。页面另按影响核对切换后编辑指定目标、批量撤销、新建不切换、通知撤销新增、已有内容时拒删、刷新保存与 JSON 回导。协议、当前 Codex 与界面三类证据分开记录；未执行的自然到期或其他路径须明确列为未覆盖，独立 SDK、app-server、HTTP 可达或历史结果不能代替当前聊天的实际工具成功。

| 路径 | 要确认的行为 |
| --- | --- |
| 加载 | `index.html` 和 `guided.html` 正常显示，脚本 / 样式无 404，控制台无错误 |
| 编辑与分支 | 双击原位编辑多行文字，点击空白完成；Tab 新分支并正确连线 |
| 拖动与关系 | 拖动卡片后坐标改变、连线跟随；跨分支连接可选中并单独删除 |
| 撤销重做 | 删节点清理关联，撤销恢复节点及连线；切换画布不串用历史 |
| 画布视图 | 空白拖动、缩放与显示全部正常，位置与连线保持一致 |
| 保存 | 等待保存状态完成后刷新，文字、位置、颜色和连接仍在 |
| JSON 回导 | 下载真实文件再选择导入；追加副本，原记录和内部连接保留；无效文件禁止导入 |

| 跨页冲突 | 两页竞争编辑时暂停覆盖，可导出本页或保留副本；双方内容可恢复 |
| MCP 只读 | 默认只读，本机 stdio / 远程 HTTP 配置分别可加载；六个工具可见，列举 / 读取 / 导出成功，编辑及新建拒绝；未授权 / 错误令牌不能读取 |
| MCP 授权时长 | 本机与线上均显示 15 分钟、1 小时、永久（直到断开），默认 1 小时及只读；有限授权返回到期时间，刷新 / 关闭仍失效；永久返回 `expiresAt: null`，刷新、重开及服务恢复后签名建立新会话并恢复原权限，旧授权不自动升级 |
| MCP 跨画布 | 面板显示当前浏览器当前站点全部画布；切换、新建、删除和追加导入后接入有效；编辑明确目标 ID，不改用户活动画布；旧单画布令牌拒绝跨画布且不自动升级 |
| MCP 读写与新建 | 先读版本，再批量创建卡片、更新、连线、删除；成功时保存已完成，在目标画布可撤销重做；新建须工作区版本且默认不切换，通知可撤销新增，已改内容时拒删 |
| MCP 导出 | 只读可导出指定单张或全部，返回字符串及文件名，不强制浏览器下载；实际保存为文件后可追加回导，名称 / 卡片 / 关系保留且不含凭据 |
| MCP 冲突与撤销授权 | 旧内容 / 工作区版本、无效操作、编辑中、拖动、未保存、导入和跨页冲突拒写；断开、刷新、关闭、过期使原会话失效；等待写锁或摘要期间断开也不提交，恢复新会话不能复活旧请求 |
| 配对与永久恢复 | 保持 Pages / 本机地址、原 localStorage 与 JSON 不变；固定身份、永久授权意愿与活跃会话分开；仅有身份时发现工具但不读取；永久刷新、重开、失联或服务恢复后保留原权限，关闭后重开实测耗时，锁证据成立时无需等待旧会话失联，不改配置或重连 Codex；有限授权不自动恢复 |
| 配对跨页与断开 | 第二页不能静默抢占仍持锁的活页（包括后台页）；无旧页关闭证据时保留原失联兜底；明确改由此页授权后原页和在途请求失效；旧页释放不影响新页；任一页主动断开后永久授权意愿清除，所有页停止恢复，刷新 / 重开不复活；取消配对后身份拒绝，清理配对不删除画布 |

旧六步工具改动时，另核对记录编辑、删除解除关联、JSON 回导与刷新保存。服务改动时，核对入口 / 模块可访问、私有目录不公开、仅回环监听、重复启动复用和无关端口占用的报错。

## Git 交付操作

默认授权、分支隔离、失败处理与清理规则统一以 [AGENTS.md 的版本管理约定](../AGENTS.md#版本管理)为准。本节列出执行顺序；用户只需提出需求，AI 按适用范围完成收尾。

1. **准备任务。** 检查 `git status`、`git diff` 和暂存区，核对 `origin` 指向本项目，再执行 `git fetch origin`。从最新 `origin/main` 创建 `codex/<task-name>`；存在并行任务时使用独立 worktree，保留已有修改。
2. **实现与验证。** 完成改动及必要文档更新；首次开发或依赖变化时执行 `npm ci`，提交前运行 `npm run verify`（依次执行 `npm run check` 和 `npm test`）。界面、MCP 等改动按上文补充对应实际验证，记录当次日期、范围、结果及限制。
3. **复核并提交。** 按文件或代码块精确暂存本任务内容，检查 `git diff --cached`、`git diff --check` 与隐私，再创建可独立理解和回退的提交。没有实际改动时直接报告结论。
4. **同步并合入。** 再次 `git fetch origin`，在任务分支整合最新 `origin/main` 并验证受影响部分。确认目标 `main` 工作区没有其他未完成工作，且 `git log origin/main..main` 不含其他任务的未推送提交后合入，线性关系优先使用 `git merge --ff-only`，再 `git push origin main`。推送被远端新提交拒绝时重新读取、整合和验证；保护要求 PR 时按其规则创建并合并，不强推或降低保护。
5. **确认发布。** 查看本次提交对应的 Actions，确认构建和部署均成功，再按影响范围核对线上地址、资源或功能；发布与后端步骤见 [部署说明](deployment.md)。纯文档修改仍确认本次 Pages 部署和线上可访问性，无需重做未受影响的界面或 MCP 验收。部署未完成时明确报告当前状态，失败处理遵循 AGENTS.md。
6. **清理并交付。** 完成上述适用验收后，回到安全的保留分支，使用 `git branch -d` 删除本任务已合并分支；若曾推送该任务分支，再核对合并结果并删除对应远端分支。临时 worktree 先确认无未提交修改，并核查、保留需要的未跟踪或忽略文件，再用创建它的工具清理。报告改动、验证、提交号、分支与上线状态及剩余限制。
