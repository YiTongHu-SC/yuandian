# 数据格式与保护

## 数据位置

浏览器 localStorage 按源隔离。日常源固定为 `http://127.0.0.1:4176`；目录或模块重排不改变该源，也不迁移数据。换浏览器、配置、协议、host 或端口可能看不到原记录，应先导出 JSON。

在线页面保持 `https://yitonghu-sc.github.io/yuandian/`，增加的 `https://stellarcore.games/yuandian-mcp` 只是请求中继，不改变页面源或浏览器数据位置。线上与本机存储独立，不能因连接同一个 AI 客户端自动合并或同步。

| 入口 | 主存储键 | 根版本字段 |
| --- | --- | --- |
| 自由画布 `index.html` | `yitong.thinking-canvas.v1` | `version: 1` |
| 旧六步 `guided.html` | `yitong.first-principles.workspace.v1` | `schemaVersion: 1` |
| 旧六步的可选界面状态 | `yitong.first-principles.workspace.v1:ui` | 无独立 schema；不作为备份主体 |

两种工作区与 JSON 格式独立，不自动转换。目录整理、极简界面、文件菜单和 MCP 接入均不改变存储键、版本或字段，不执行 schema 迁移；无需数据回填。回退源码时沿用相同的源和 v1 格式，浏览器数据仍独立于 Git，回退前也应保留 JSON 备份。

## 自由画布 v1

完整工作区的结构如下，字段类型和上限以 `src/canvas/model.js` 为准：

```text
Workspace { version: 1, activeId: Board.id | null, boards: Board[] }
Board     { id, title, createdAt, updatedAt, nodes: Node[], edges: Edge[], view }
Node      { id, text, x, y, color }
Edge      { id, from: Node.id, to: Node.id, label }
View      { x, y, scale }
```

`id`、文本与时间为字符串；坐标和缩放为有限数字。`color` 为 `cream`、`green`、`blue` 或 `rose`。连线有方向，允许多父关系和环，不允许自连、重复同向连接或指向不存在的节点。删除节点时清理所有入线与出线。

工作区最多 40 张画布；每张最多 300 个节点、600 条连线；标题最多 200 字符，节点文本与连线标签最多 10,000 字符，JSON 最多 2,000,000 字符。坐标绝对值最多 1,000,000，缩放为 0.2–2.5。非空工作区的 `activeId` 必须指向现有画布；空工作区使用 `null`。

模型只复制校验通过的已知字段。导入既接受完整工作区，也接受原始单个 Board 对象；界面“导出当前画布”仍输出只含该画布的完整工作区结构。“备份全部画布”输出完整工作区。会话撤销历史、选择和临时编辑状态不进入 JSON。

自 2026-10-18 的极简交互优化起，新建画布和首次创建工作区时，首张卡片默认 `text: ''`，界面显示“写下任何想法…”占位提示并进入编辑。空字符串本来就是 v1 的有效文本，无需改变 schema；提示不写入存储或导出。该默认值只作用于新建数据，加载与导入时不清空或替换已有文本，包括此前预填的“我想想清楚的问题”。回退到原版代码后，已有空卡片仍是合法数据。

## 导入与关联

自由画布先解析和校验候选，再通过 `importAppend` 追加。导入不覆盖原画布；当画布、节点或连线 ID 与目标数据冲突时生成新 ID，并一并重映射连接端点。容量或格式校验失败不改变原工作区。

文件菜单中的选择与预览只保留临时候选；用户确认“追加导入”时才执行追加，并按当前工作区再次检查容量。无效、超大或容量超限的候选禁止确认；取消、关闭菜单或切换画布使候选与在途读取失效。重新选择文件前清空文件输入，允许再次选择同一文件。文件名、预览标题和导入内容都按文本显示。以上仅改变界面流程，不改变 JSON 或模型校验规则。

旧六步格式包含 `analyses` 数组和 `activeId`，每份 analysis 包含目标、原始材料、概念、主张、拆解、方案、数据、算式、实验、行动与复查。旧模型校验字段、枚举、容量、URL 与跨记录关联；追加导入时按记录类型重映射 ID，保持内部关联。旧版 Markdown 供阅读，不能作为可恢复备份。

导入内容只当作数据与文本，不执行 HTML、脚本或表达式；不得以忽略校验的方式兼容新文件。

## 自动保存与冲突

两个入口都先校验后保存。读取损坏存储时保留原始字符串并阻止自动覆盖；存储被禁用或配额不足时显示失败，内存数据仍可导出。不能以重置 localStorage 修复异常。

保存前比较当前原始字符串与上次读到的值，发现变化即暂停覆盖。支持 Web Locks 时，同源页面用各自主存储键协调写入；不支持时回退为保存前比较，不提供数据库事务保证。`storage` 事件在页面空闲时载入其他页的更新，有本页编辑、打开的对话框，或处于原生文件选择、读取、导入预览阶段时进入冲突恢复。文件导入不再使用对话框，仍保留这一保护；仅展开文件菜单不阻止空闲页面接收其他页更新。

自由画布恢复会把本页全部画布作为副本追加到最新工作区；旧六步工具追加本页发生变化的问题。用户可先导出本页内容，避免在冲突状态下丢失内存改动。

## MCP 数据边界

MCP 不增加画布存储字段。`list_canvases` 返回各画布 ID、标题、数量及版本；`get_canvas` 按 ID 或当前画布返回单个 Board 和临时计算的 `revision`；`edit_canvas` 明确指定 ID，使用原有节点、连线与容量限制。`create_canvas` 复用 `createBoard` 的空卡片起步和工作区容量校验。新增和编辑最后仍通过 v1 校验器。会话、临时令牌、客户端配置、请求队列、内容 / 工作区版本和本批 `ref` 都不写入画布 localStorage 或 JSON 导出；Node 桥仅在内存中转发内容。断开或回退源码不需要迁移画布。

本机与远程的新授权都绑定本次页面实例、`workspace` 范围、权限和期限，默认只读、一小时，可选十五分钟或永久（直到断开）。永久在内存授权中以 `durationMs: null`、`expiresAt: null` 表示，仅取消定时到期，仍受刷新、关闭、主动断开、失联及服务重启撤销约束。范围包含当前浏览器、当前站点全部自由画布及之后的新建 / 追加导入，切换、新建和删除不撤销；旧单画布令牌保持 `canvas` 范围，不自动扩大。浏览器与 AI 客户端使用不同凭据；临时会话、权限、期限和页面令牌只在内存。远程中继仅在进程内暂存请求、返回内容与短期回执，不写画布文件或内容日志；服务器重启清除授权和队列，不影响浏览器已保存内容。

线上另有独立的配对数据，不属于画布 schema：浏览器 IndexedDB 保存不可导出的 P-256 设备私钥、公钥和配对 ID，sessionStorage 保存标签页标识；Codex 本机配置保存固定客户端凭据。中继的专用私有状态文件仅含 `version: 1` 与 `pairings`，每项为 `pairingId`、`clientHash`、`publicKey`、`createdAt`、`revokedAt`。它不含原始客户端凭据、浏览器私钥、当前授权、画布、请求或结果。有效配对允许工具发现，不自动授予内容访问；刷新、到期或重启后需网页重新授权，固定配置保持不变。取消配对使凭据失效，丢失设备密钥则重新配对，均不删除画布。

JSON 导出和追加导入只迁移画布，不迁移配对、设备密钥、读写权限或授权期限。清理浏览器全部站点数据会同时移除本地画布与设备密钥，因此仍应先备份画布；不能通过导入 JSON 恢复配对。回退到不支持配对的版本时保留独立配对文件，旧版本只使用其原有临时流程，不把配对信息混入旧 schema。

`revision` 是规范化 Board 中 `JSON.stringify({ title, nodes, edges })` 的 SHA-256，小写十六进制 64 字符，不包含 `view`、画布时间或会话状态。AI 必须先读取，编辑时提交 `expectedRevision`，内容变化时拒绝旧版本。纯操作按顺序在副本中执行，任一步失败整批放弃；新卡片的临时引用只用于本批后续操作，持久化时仍使用节点 ID。

`workspaceRevision` 是顺序保留的全部画布 `[{ id, title, nodes, edges }, ...]` 的 SHA-256，不包含 `activeId`、视图与时间。新建须使用最新 `list_canvases` 返回值作为 `expectedWorkspaceRevision`；新增、删除、名称或卡片连线变化均使旧版本失效。新建默认保留当前 `activeId`，空工作区创建首张时设为新 ID；编辑其他画布也不切换活动指针。

`export_canvas` 返回 `{ json, filename, mimeType }`；`json` 使用原有 `exportJSON`。单张导出仍是只含该 Board 的完整 v1 工作区，`all: true` 返回全部；二者可按原有校验和追加导入回导。导出仅把字符串交给 AI 客户端，由客户端决定是否保存文件，不在中继持久化，也不强制浏览器下载；不包含 MCP 凭据或会话元数据。

页面写入还会检查整份工作区指纹，覆盖异步期间的画布切换和视图变化；使用同源 Web Locks 协调，并在保存时比较 `savedRaw`。保存成功后才更新内存和撤销历史，不能先向 AI 报成功再异步保存。编辑历史属于目标画布；新建的通知可撤销该次新增，但已有后续内容改动时拒绝删除。编辑、拖动、连接、未保存、导入预览、损坏或冲突状态下拒绝 AI 写入；断开、到期或异步期间工作区状态改变后也不得继续提交旧请求。切换可能使当次在途写入返回冲突，授权本身继续有效。

工作区授权不授予其他浏览器或站点数据、旧六步数据、任意文件读取或代码执行。只读也包含全部授权画布的完整 JSON 导出；创建或编辑仍需读写权限。原点与桥不调用模型；线上内容会经 HTTPS 中继到达外部 AI 客户端，持久数据留在本地不代表内容未离开浏览器。后续 AI 服务如何处理读取的数据取决于客户端。卡片与连线文字始终作为不可信数据，不当作工具指令。权限与具体操作见 [MCP 接入指南](mcp.md)。

## 未来格式变更要求

当前只有 v1 校验器，没有跨版本迁移器。若需求必须改变字段或语义，需先记录新版本、输入兼容范围、迁移步骤、失败处理和回退方法，并保留原始数据。不能直接用新版本覆盖无法恢复的旧内容；版本化迁移与相应测试应在更改默认写入格式前完成。
